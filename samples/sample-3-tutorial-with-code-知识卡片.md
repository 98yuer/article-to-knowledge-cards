# 用生成器处理大文件 知识卡片

> 来源：`samples/sample-3-tutorial-with-code.md`

### 卡片 1：生成器要解决的真实问题

- **核心知识**：把整个文件一次性读进内存会打满内存，生成器的做法是每次只产出一条、处理一条。
- **简明解释**：`open(f).readlines()` 会把文件全部内容驻留在内存中，10GB 的日志直接撑爆。生成器的内存占用始终只等于一条记录的大小，因为它不做整体载入。
- **例子/自测**：原文场景：处理 10GB 日志文件时，`readlines()` 会直接把内存打满。
- **来源**："为什么要用生成器"一节

### 卡片 2：yield 的暂停与继续

- **核心知识**：执行到 `yield` 时函数把值交出并原地暂停，下一次调用从暂停处继续。
- **简明解释**：这是生成器区别于普通函数的关键——普通函数 `return` 后状态清空，而 `yield` 保留了局部变量状态，同时避免反复重建函数栈。
- **例子/自测**：问：第二次从生成器取值时，函数从哪里开始执行？答：从上次 `yield` 暂停的位置继续，局部变量保持原值。
- **来源**："为什么要用生成器"一节后段

### 卡片 3：基本写法是替迭代封一层 def

- **核心知识**：写一个带 `yield` 的函数包住数据源，再用 for 循环消费它。
- **简明解释**：函数内部负责逐条产出，调用方负责逐条处理，读取与业务逻辑因此解耦。
- **例子/自测**：原文示例：

  ```python
  def read_lines(path):
      with open(path, encoding="utf-8") as f:
          for line in f:
              yield line.strip()

  for line in read_lines("access.log"):
      handle(line)
  ```

- **来源**："基本写法"一节

### 卡片 4：套一层 list() 就让省内存失效

- **核心知识**：对生成器调用 `list()` 会触发一次性求值，惰性全部作废。
- **简明解释**：`list()` 必须拿到所有元素才能构造列表，于是生成器被从头到尾跑完，数据再次全部进入内存——这是原文点出的最常见误用。
- **例子/自测**：问：把 `read_lines("access.log")` 改成 `list(read_lines("access.log"))` 会怎样？答：生成器被一次性求值，省内存效果完全消失。
- **来源**："基本写法"一节后段

### 卡片 5：函数与生成器表达式的取舍

- **核心知识**：逻辑在一行以内用圆括号的生成器表达式，超过一行就写成带 `yield` 的函数。
- **简明解释**：生成器表达式省掉一个 `def`，写法紧凑；但塞进多行逻辑后可读性会迅速变差，此时函数的表达力更优。
- **例子/自测**：原文示例：

  ```python
  total = sum(int(x) for x in read_lines("nums.txt"))
  ```

- **来源**："生成器表达式"一节

### 卡片 6：多级串联仍然是逐元素流动

- **核心知识**：把多个生成器串成管道时，每一步过滤在上一步产出单个元素的瞬间就发生，不需要中间列表。
- **简明解释**：串联的每一级本身是惰性的，数据在管道里逐条流动而非逐级堆积。整个链条在消费者真正开始遍历前，一行数据都不会被读取。
- **例子/自测**：原文指出 `for` 循环真正执行前，这段管道一行都没读：

  ```python
  lines = read_lines("access.log")
  errors = (l for l in lines if "ERROR" in l)
  ```

- **来源**："管道式串联"一节

### 卡片 7：生成器是一次性的

- **核心知识**：生成器对象迭代完之后再遍历它，什么都取不到。
- **简明解释**：`yield` 走到底后迭代器耗尽，不像列表那样可以反复遍历。原文给出的两个对策：重新调用生成函数，或用 `itertools.tee()`。
- **例子/自测**：问：需要两次遍历同一份数据时怎么办？答：重新调用生成函数，或使用 `itertools.tee()`。
- **来源**："两个坑"第一条

### 卡片 8：复杂函数里的多个 yield 难以调试

- **核心知识**：在有装饰器或异常捕获的长函数中写多个 `yield`，暂停点会让调试变得困难。
- **简明解释**：多个暂停点交织叠加了控制流，出错时难以定位执行位置。原文的取舍建议：宁可拆成两个简单生成器。
- **例子/自测**：问：一个 200 行的函数里要写五个 `yield`，更好的做法是什么？答：拆成多个简单生成器，而不是全塞进一个函数。
- **来源**："两个坑"第二条
