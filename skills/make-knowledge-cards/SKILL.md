# Make Knowledge Cards

## Overview

把一段学习材料（粘贴的文章正文，或本地 `.md` / `.txt` 文件）压缩成 5~8 张自足的知识卡片。

卡片不是摘要。摘要是压缩原文，卡片是重构知识——每张卡片必须能在脱离原文的情况下独立读懂，且只承载一个知识点。

核心原则优先级：**准确 > 有用 > 数量**。凑不够 5 张时交付实际存在的数量，不注水。

## 适用范围

**使用本 skill 的场景：**

- 用户粘贴一段文章正文，要求做成卡片、提炼知识点、整理成复习材料
- 用户给出本地 `.md` / `.txt` 文件路径，要求转成知识卡片
- 用户说"帮我把这篇文章变成能背的版本""提取核心考点"

**明确不支持（遇到时直接说明不支持，不要绕路实现）：**

- 网页抓取：不抓取 URL 页面。需要时请用户先粘贴正文或另存为 Markdown
- PDF / DOCX / CAJ：不解析这类二进制文档（含知网的 `.caj`、`.kdh`，以及 Word 的 `.docx`）。请用户用原阅读器或 Word 的"另存为"导出成 `.txt`
- Anki：不生成 `.apkg` 或制表符分隔的 Anki 导入文件（用户后续可自行从 Markdown 转换）
- 图形界面：不生成图片、HTML 网页或可视化排版，输出为纯 Markdown

遇到不支持的格式时，不要尝试自行安装第三方转换器或绕路解析，直接说明不支持并给出转换路径："这个文件是 XX 格式，本 skill 只处理 md/txt；请用 XX 打开后另存为 TXT 再给我，或把正文直接粘贴进来。"

## 工作流

### Step 1 — 获取素材

- **本地文件**：用 Read 工具读取 `.md` / `.txt` 内容；其他扩展名（PDF、DOCX、CAJ 等）先说明不支持，不要尝试用第三方工具转换（见"适用范围"的话术）
- **粘贴文本**：直接使用对话中的文本；正文过短（见"数量判断规则"）时先提示用户材料不足
- **两者都没有**：先要素材，不要凭主题自行生成
- **两者都有**：以文件内容为准，粘贴部分视为补充或删减指令

### Step 2 — 通读并列出候选知识点

按素材类型选择抓取重点（见"素材类型适配"），在内部草稿中先列出候选清单，每条一行，标注它在原文的位置（有小标题用节名，没有则用"第 N 段"）。

按下列类型抓候选：

1. 作者明确定性的概念定义与原理
2. 因果链 / 机制解释（什么导致什么）
3. 判断标准、成立条件、边界（何时适用、何时失效）
4. 反直觉或有代价的结论（常见错误、权衡取舍）
5. 可复用的操作步骤 / 方法
6. 原文自带的典型例子、数据或案例

**不进候选清单：** 作者介绍、前言致谢、重复强调的套话、单纯的背景铺垫、没有信息量的过渡段。

### Step 3 — 筛选与去重

对候选清单按顺序做三件事：

1. **砍**：连续自问"读者记不住这一条会损失什么？"——答不上来就删。目标是留下最少的高价值点，不是最多的点。
2. **合**：把讲同一件事的多段叙述合并成一张卡（原文常在开头和结尾各讲一遍同一原则）。判断标准：两张卡的核心知识若能合并成一句话而不丢信息，就必须合并。
3. **排**：按认知顺序而非原文顺序排列。推荐顺序：定义 → 机制 → 条件与边界 → 易错点 → 应用。

### Step 4 — 写卡片

每张卡片严格使用以下固定字段模板，不要增删字段，不要改字段名：

```markdown
### 卡片 N：<标题>

- **核心知识**：<一句话结论，最多 2 句，必须自足完整>
- **简明解释**：<用自己的话展开 2~4 句，解释原理、原因或适用前提>
- **例子/自测**：<例子或自测问题，二选一，见下方规则>
- **来源**：<原文位置，如"第 3 节"或"原文第 2 段">
```

字段填写规则：

- **标题**：不超过 20 字，是具体的知识点名称，不要直接复制原文小标题，不要用"关于……的介绍"这类泛泛句式
- **核心知识**：唯一的、可被检验的结论句。不写推理过程，不写例子。读者只读这一行也要能抓住要点
- **简明解释**：解释为什么成立、什么时候成立。禁止复制原文长句，必须改写
- **例子/自测**：
  - 优先使用原文给出的例子或数据，保留原文数字，禁止改写数字
  - 原文没有例子时，写一个自测问题（格式：问：…… 答：……），答案必须能在原文中找到依据
  - 不要凭空编造原文未出现的具体案例、公司名、人名、数据
  - 技术类素材允许在此字段内嵌 fenced 代码块，限 3~8 行、只截取论证该知识点必需的部分
- **来源**：指向原文的具体位置，便于回溯核证

**信息缺失时的写法**：某字段在原文里确实查不到时，写"原文未给出……"明确标注，不要留空、不要用常识补写、不要为了版面好看而舍掉该字段。

### Step 5 — 出卡前自检

逐条核对，任何一条不过就改：

- [ ] 卡片数量在 5~8 张之间；或在材料不足时按实际数量输出并已说明原因
- [ ] 每张卡片只有一个知识点；一张卡里出现两个并列结论必须拆开
- [ ] 任意两张卡片的核心知识不重复、不高度重叠
- [ ] 每张卡片的每个事实都能在原文中定位，来源字段已填
- [ ] 没有任何原文之外的事实、数字、因果关系、术语定义
- [ ] 解释是改写而非复制原文；例子中的数字与原文完全一致
- [ ] 标题具体不泛；四个字段齐全，格式与模板一致

### Step 6 — 输出

1. **写文件**：默认用 Write 工具写入 `<原文文件名>-知识卡片.md`（粘贴文本时用 `<主题短语>-知识卡片.md`），放在工作区根目录或用户指定路径
2. **文件结构**：第一行 `# <主题> 知识卡片`，第二行来源说明（源文件名或"来自用户粘贴文本"），然后是卡片正文
3. **回复摘要**：对话中只回三件事——卡片数量、卡片标题列表、以及未覆盖内容的提醒（例如某段因重复或信息不足未成卡）。不要把卡片全文复制到对话里

**注意**：未覆盖内容的提醒只陈述**原文中确实存在但被舍弃或合并的内容**，禁止在提醒里引入任何原文没有的背景、出处或推测——这是最容易发生编造的位置，写完再核一遍。

## 素材类型适配

不同素材的知识密度差异很大，按类型调整抓取重点：

| 类型 | 特征 | 抓取重点 | 卡片组织 |
| --- | --- | --- | --- |
| 概念说明型 | 论述文、教材节选，有定义有论证 | 定义、机制、边界条件、反直觉结论 | 定义 → 机制 → 边界 → 易错点 → 应用 |
| 教程操作型 | 含代码/操作步骤，讲"怎么做" | 为什么这样做、关键机制、写法取舍、常见坑 | 动机 → 机制 → 写法 → 误用 → 边界 |
| 清单罗列型 | 若干条并列建议，每条无展开 | 每条是否真的讲了道理/给了依据 | 见"数量判断规则"的处理分支 |
| 学术文献型 | 摘要、引言、结论与政策建议齐备，常有缺失的公式与表格 | 摘要与结论节的成体系结论、机制解释、边界条件 | 框架 → 核心结论 → 分情形异质性 → 调节因素 → 边界 |

教程操作型的两条补充规则：

- 操作步骤本身可以成卡，但卡片标题必须体现**这一步解决什么问题**，不要写成"第 3 步：XXX"
- 代码放进"例子/自测"字段时保持缩进对齐（列表项内嵌代码块需缩进 2 空格），只截取必需片段；完整代码留给原文，不做搬运

学术文献型的四条补充规则：

- 优先读**摘要和结论节**，那里有作者自己认定的核心结论，不要从零散段落里拼结论
- 文献综述、背景铺垫、边际贡献、参考文献、作者简介一律不进候选清单
- 粘贴的论文正文常丢失公式和表格（只剩"式（3）""见表 2"这类引用）。**不要试图还原或推导缺失的公式**，卡片只建立在可见的文字结论上，并在文件头注明"公式/表格已缺失"
- 实证类结论写显著性时带上原文的水平（如"1% 水平显著为正"），不要把不显著的结果写成成立——"系数为负但不显著"必须照实写，这是学术素材最容易失真的地方

## 数量判断规则

- 能产出 8 张以上符合条件的卡片时，只保留价值最高的 8 张，其余在回复中提一句已被取舍
- 只能产出 5~7 张时，按实际数量输出，不补足
- 用户明确指定数量（如"就做 6 张"）时按指定数量输出，但如果原文只能支撑更少，**先说明缺口再询问**，不要为凑到指定数重复或注水
- 产出不足 5 张时，照实输出并明确告知："原文可提炼的独立知识点只有 N 个，凑到 5 张会引入重复或编造，因此保留 N 张。"再询问是否需要补充材料
- 原文极短或纯列表无展开时（每条只有一句话、没有理由或依据），**不要直接出卡**。先说明为什么这批素材撑不起卡片——"简明解释"字段会无米下锅，硬写就是编造——然后给用户两个选项：(1) 补充带解释的正文再来做；(2) 接受标注了"原文未给出理由"的弱卡片。等用户选择后再动手，不要自作主张同时把两件事都做了

## 反编造红线

以下行为一律禁止：

- 补充原文没有的背景知识、常识、"顺便说一下"
- 把原文的"部分情况"写成"所有情况"，把"可能""作者推测"写成确定结论
- 用原文的术语去套一个原文并未提到的场景
- 生成原文中不存在的数字、年份、人名、机构名、研究结论
- 用"一般来说""众所周知"等模糊措辞掩盖无依据的表述
- 在"未覆盖内容提醒"或文件头的背景介绍里夹带原文没有的出处、作者意图、适用推论
- 把原文举例中的"某方案更好"扩展成"某方案在所有情况下都更好"

不确定时的处理办法：宁可删掉这张卡，也不要带着不确定内容输出。

## 常见失败模式

| 失败模式 | 修正动作 |
| --- | --- |
| 卡片只是原文段落的改写，读完抓不到要点 | 把核心知识重写为一句独立结论，解释移到简明解释字段 |
| 一张卡塞了多个知识点 | 按知识点拆卡，超出 8 张再砍掉低价值的 |
| 前后两张卡表述同一件事 | 合并，或删除价值较低的一张 |
| 例子是凭空编的 | 换成原文例子，或改成自测问题（答案须有原文依据） |
| 为凑 8 张把套话也做成卡 | 按实际数量输出并说明原因 |
| 解释字段抄了原文一大段 | 限制在 2~4 句并改写 |
| 教程类素材把整段代码搬进卡片 | 只截取必需的 3~8 行放进例子字段，并缩进对齐 |
| 卡片标题写成"第 3 步：XXX" | 改成这一步解决的问题，如"用 yield 保留函数状态" |

## 完整示例

**输入（用户粘贴）：**

> 睡眠不足会削弱前额叶皮层对杏仁核的抑制，导致情绪反应放大 60% 以上。实验显示，连续 5 天只睡 5 小时的人，其情绪波动幅度接近正常睡眠者的两倍。这种影响在 REM 睡眠被剥夺时尤其明显。值得注意的是，补觉并不能立即恢复，通常需要连续两晚正常睡眠才能回到基线。

**输出片段：**

```markdown
### 卡片 1：睡眠不足放大情绪反应的机制

- **核心知识**：睡眠不足会削弱前额叶皮层对杏仁核的抑制，使情绪反应被放大。
- **简明解释**：前额叶平时负责压制杏仁核的情绪冲动。睡眠不足时这层"刹车"变弱，杏仁核反应因此失控放大——这是生理机制，不是意志力问题。
- **例子/自测**：原文实验数据：连续 5 天只睡 5 小时的人，情绪波动幅度接近正常睡眠者的两倍。
- **来源**：原文第 1~2 句

### 卡片 2：REM 阶段剥夺的影响

- **核心知识**：睡眠不足对情绪的影响在 REM 睡眠被剥夺时尤其明显。
- **简明解释**：REM 阶段与情绪调节关系最密切，因此缺失这一阶段造成的损害大于单纯减少总睡眠时长。
- **例子/自测**：问：同样是睡眠不足，哪种情况对情绪伤害更大？答：REM 睡眠被剥夺的情况（原文明确指出其影响尤其明显）。
- **来源**：原文第 3 句

### 卡片 3：补觉的恢复速度

- **核心知识**：补觉无法立即恢复情绪调节能力，通常需要连续两晚正常睡眠才能回到基线。
- **简明解释**：情绪功能的恢复滞后于睡眠时长的补偿，单次补觉不够——熬夜欠下的账要分多次还。
- **例子/自测**：问：熬夜一周后睡一整天能补回来吗？答：不能。原文指出需连续两晚正常睡眠才能回到基线。
- **来源**：原文第 4 句
```

本例输入只能支撑 3 张互不重复的卡片，因此输出 3 张而非凑到 5 张——这是正确行为。
